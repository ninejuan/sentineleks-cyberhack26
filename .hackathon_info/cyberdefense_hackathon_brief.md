# Cyberdefense Hackathon — AI Context Brief

> **용도:** AI 코딩 에이전트, 아이디어 기획 AI, 프로젝트 리뷰 AI에 제공할 수 있는 해커톤 요구사항 정리.
> **출처:** 사용자가 촬영한 행사 슬라이드 4장(Challenge Statement, Judging Criteria, Project Submission, Sponsors). 행사 페이지에서 확인한 추가 배경은 별도 구분한다.

## TL;DR

- **목표:** 공개 웹(open web)에서 **실제로 일을 수행하는 자율 에이전트**를 만들어 배포/시연한다.
- **행동 요구:** 단순 질문 답변이나 분석에 머무르지 않고 **게시(publish), 모니터링(monitor), 오케스트레이션(orchestrate), 거래/작업 실행(transact)** 등 실제 행동을 수행해야 한다. 이들은 슬라이드에 나온 행동 예시이며, 네 가지를 모두 구현해야 한다고 쓰여 있지는 않다.
- **신뢰성:** 실제 데이터와 **진실성 있는 출처(truthful sources)** 에 근거해야 한다.
- **도구:** **스폰서 도구 최소 3개 이상**을 효과적으로 사용한다.
- **심사:** 자율성, 아이디어의 현실적 가치, 기술 구현, 스폰서 도구 활용, 3분 데모.
- **제출:** **오후 4:30까지**, 팀당 1건, 팀당 최대 4명, **3분 데모 녹화 영상** 포함.
- **제출 URL:** https://tokensand.com/cyberhack/submit

## 1. Challenge Statement (현장 슬라이드 원문)

> Build agents that preserve what matters.
>
> Ship an autonomous agent that does real work on the open web.
>
> Your agent(s) need to take real action — publish, monitor, orchestrate, transact — grounded in truthful sources. Use 3+ sponsor tools.

### 한국어 해석

**지켜야 할 중요한 것을 보호하는 에이전트를 만들어라.** 공개 웹에서 단순히 제안만 하는 것이 아니라 실제 업무를 수행하는 자율 에이전트를 구현한다. 게시, 모니터링, 시스템 간 조정, 트랜잭션 수행 등 실제 행동을 하고, 신뢰 가능한 사실/출처를 기반으로 하며, 3개 이상의 스폰서 도구를 사용한다.

### 요구사항과 예시의 구분

| 구분 | 내용 |
| --- | --- |
| 도전 과제 | Open web에서 실제 업무를 수행하는 자율 에이전트 구축 |
| 행동 | 실제 액션 수행 필수; publish/monitor/orchestrate/transact는 슬라이드의 예시 |
| 근거 | 실시간 데이터 및 사실에 기반한 정보·출처 활용 |
| 스폰서 도구 | 최소 3개 이상을 **효과적으로** 활용 |
| 범위 | 현장 슬라이드는 특정 구현 언어, 프레임워크, 클라우드 또는 특정 스폰서를 필수로 지정하지 않음 |

## 5. 추가 배경: 행사 소개 페이지 기준 (슬라이드 외 정보)

행사 소개 페이지는 사이버 방어 영역의 예시를 다음과 같이 제시한다. **아래 네 가지는 행사 방향을 이해하기 위한 예시이며, 사진의 필수 제출 항목으로 명시된 것은 아니다.**

1. **Threat discovery:** 악용되기 전 취약점·설정 오류·공격 경로 발견
2. **Attack intelligence:** 파편화된 신호를 연결해 현재 일어나는 상황 파악
3. **Autonomous remediation:** 최소한의 인간 개입으로 패치·강화·조치 확인
4. **Continuous defense:** 지속적으로 모니터링하고 적응하며 위협에 대응

행사 소개: https://luma.com/cyberhack

## 6. AI에게 적용할 해석 원칙 (공식 규정 아님)

다음은 **제작/검토를 위한 제안**이며 심사위원이 공표한 추가 규칙이 아니다.

- 에이전트가 **관찰 → 판단 → 외부 액션 → 결과 검증**의 흐름을 끊기지 않게 수행하는 모습을 보여준다.
- 데이터의 출처, 관측 시각, 결정 근거, 외부 액션의 성공/실패 결과를 로그로 남긴다.
- 스폰서 도구를 개수만 맞추려고 붙이지 말고, 각 도구가 맡는 기능을 명확히 연결한다.
- 3분 데모에서는 문제, 실행 과정, 실제 결과, 사용한 3개 이상 스폰서 도구를 식별 가능하게 보여준다.
- 사이버 보안 프로젝트는 권한 있는 환경/대상에서 테스트하고, 파괴적이거나 위험한 행동은 적절히 제한한다.

## 7. 사진/공식 자료만으로 확인되지 않은 항목

다음 내용은 **임의로 채워 넣지 말 것**:

- 심사 항목별 가중치·점수
- 제출 마감의 정확한 시간대 및 허용되는 지각 제출 여부
- 데모 영상의 업로드 형식·용량·호스팅 규칙
- GitHub 저장소, 소스코드, 슬라이드 별도 제출의 필수 여부
- 각 스폰서상의 상세 조건, 수상 금액, 중복 수상 가능 여부
- 스폰서 도구의 인정 기준과 제공 계정/API/크레딧 범위

## 8. AI 프로젝트 기획 및 검증용 작업 지시

이 문서를 프로젝트 요구사항의 기준으로 사용할 때:

1. 제안하는 프로젝트가 **실제 사이버 방어 문제**를 어떻게 해결하는지 2~3문장으로 요약한다.
2. 실제로 발생시키는 **웹/외부 시스템 액션**을 명시한다. 단순한 정보 조회와 실제 액션을 구분한다.
3. 최소 **3개의 스폰서 도구**를 선정하고, 각 도구의 구체적 역할과 실제 호출/동작 증거를 적는다.
4. 사용자 수동 개입 없이 동작하는 핵심 경로, 사실 검증 방식, 실패/재시도 처리 방식을 설계한다.
5. 5개 심사 항목에 따라 구현 상태를 검토하되, **존재하지 않는 배점이나 수상 확률을 만들어내지 않는다.**
6. 3분 데모 시나리오와 제출 체크리스트를 작성한다.
7. 행사에서 명시된 사실과 별도의 설계 제안을 구별하여 보고한다.
